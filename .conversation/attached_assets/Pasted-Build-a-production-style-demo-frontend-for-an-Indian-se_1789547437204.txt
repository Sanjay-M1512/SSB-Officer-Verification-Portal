==================================================
1. PROJECT PURPOSE
==================================================

The portal is an officer-facing identity verification system.

An SSB officer receives a person/document set and needs to verify whether the person's identity is consistent across:

1. Passport
2. Aadhaar Card OR Driving Licence
3. Fingerprint
4. Face verification
5. Liveness verification
6. Trusted Verification Database
7. Integrity/hash verification

The officer should be able to upload the required documents and fingerprint file, start verification, and receive a clear layered verification result.

The interface should feel like an official Indian government/security/forensic application rather than a generic SaaS dashboard.

The design should communicate:

- Security
- Identity verification
- Government/security operations
- Reliability
- Evidence integrity
- Officer workflow
- Clear decision-support information

Do NOT make the UI flashy, gaming-like, crypto-like, or startup-like.

12. REQUIRED BACKEND ENDPOINTS

The frontend should be designed around the following backend API contract.

IMPORTANT:
If the actual Flask backend already has different endpoint names, inspect the backend and use the existing routes instead of creating duplicates.

A. HEALTH CHECK

GET

/api/health

Purpose:

Check whether the backend is reachable.

Expected example:

{
"status": "ok"
}

Use this for connection/system status only.

B. IDENTITY VERIFICATION

POST

/api/verify

Content-Type:

multipart/form-data

This is the main endpoint.

Send:

passport document
Aadhaar OR driving licence
fingerprint_file

Example form-data concept:

passport = passport.jpg

identity_document = aadhaar.jpg

fingerprint_file = fingerprint.firpiv

If the existing backend uses different field names, use those exact field names.

IMPORTANT:

The frontend should NOT send manually typed Passport/Aadhaar/DL numbers when those values are produced by Module 1.

The backend should:

Receive documents
Run Module 1 OCR/document validation
Extract Passport Number
Extract Aadhaar Number OR DL Number
Search Firebase Verification DB
Retrieve trusted identity record
Retrieve enrolled fingerprint reference
Retrieve fingerprint file from IPFS if required
Extract enrolled fingerprint template
Extract new fingerprint template
Perform biometric fingerprint matching
Perform face verification
Perform liveness verification
Recalculate integrity/hash
Compare calculated hash with stored hash
Return final verification result
EXPECTED VERIFY RESPONSE

The frontend should support a response structure similar to:

{

### Backend endpoint flow to give the AI

The important part is this relationship:

```text
SSB OFFICER FRONTEND
        │
        │ POST /api/verify
        │ multipart/form-data
        ▼
┌─────────────────────────┐
│     FLASK BACKEND       │
└────────────┬────────────┘
             │
             ▼
       MODULE 1
 OCR + Document Validation
             │
             ├── Passport No
             └── Aadhaar / DL No
                       │
                       ▼
              Firebase Verification DB
                       │
                       ├── Identity Record
                       ├── Enrolled Fingerprint
                       ├── IPFS Reference
                       └── Stored Hash
                       │
                       ▼
              Fingerprint Matching
                 Template A ↔ B
                       │
                       ▼
                Face Verification
                       │
                       ▼
                Liveness Detection
                       │
                       ▼
                 Hash Verification
                       │
                       ▼
                FINAL RESULT
                       │
                       ▼
              JSON → FRONTEND

For the demo, the officer should see this as a clean sequence:

Documents → Database → Fingerprint → Face → Liveness → Integrity → Final Decision

That gives you a strong SSB Officer workflow without mixing in the Admin or Forensic portals yet.
